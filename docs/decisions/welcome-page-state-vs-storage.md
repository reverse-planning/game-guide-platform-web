## 문제 정의

로그인 직후 사용자에게 보여주는 Welcome UI를 별도의 페이지(`/welcome`)로 분리할지,  
아니면 기존 화면 내에서 일회성(one-shot) UI로 처리할지에 대한 의사결정이 필요했다.

이 결정은 다음 UX/아키텍처 요소에 영향을 준다.

- 뒤로가기 히스토리 관리
- URL 공유 가능성
- 상태 저장 범위(메모리 vs storage)
- 인증 리디렉션 흐름 단순성

특히 본 프로젝트에서는 `next` 기반 리디렉션과 인증 가드가 존재하기 때문에,  
Welcome 처리가 라우팅 복잡도를 증가시키지 않는 방향이 중요했다.

---

## 선택지 비교

### Option A. 별도 Welcome 페이지(`/welcome`)로 분리

**장점**

- URL 단위로 명확한 화면 구분
- 공유/딥링크 가능
- 라우팅 흐름이 명시적

**단점**

- 뒤로가기 히스토리 오염 가능
- 인증 리디렉션 체인 복잡도 증가
- 단발성 UI 치고는 라우팅 비용 과다
- `/ → /welcome → /guides` 같은 불필요한 이동 발생

---

### Option B. 기존 화면 내 one-shot UI 처리 (선택)

로그인 직후에만 표시되는 일회성 UI로 처리.

**장점**

- 라우팅 단순화
- 히스토리 오염 없음
- 인증 흐름과 자연스럽게 결합
- 불필요한 페이지 전환 제거

**단점**

- 새로고침 시 상태 유지 전략 필요
- 상태 전달 방식 선택 필요

---

## 판단 기준

Welcome UI를 별도 페이지로 분리할지 여부를 다음 기준으로 평가했다.

### 분리해야 하는 경우

- 딥링크/공유 가치가 있음
- 사용자가 다시 방문할 가능성이 있음
- 브라우저 히스토리 보존이 UX에 중요
- 독립적인 페이지 의미가 있음

### 분리하지 않아도 되는 경우 (본 프로젝트)

- 로그인 직후 **단 1회 노출**
- 뒤로가기 히스토리 불필요
- 공유/북마크 가치 없음
- 인증 흐름의 일부 단계에 가까움

본 프로젝트의 Welcome UI는 후자에 해당한다고 판단했다.

---

## 상태 전달 전략 비교

one-shot UI를 선택함에 따라 상태 전달 방식을 비교했다.

### 1. `location.state`

> “방금 발생한 이벤트”를 전달하는 용도

예:

- 로그인 직후
- 생성 완료 직후
- 저장 완료 직후

**장점**

- URL 오염 없음
- 라우팅 흐름과 자연스럽게 결합
- 구현 단순

**단점**

- 뒤로가기 시 state가 남을 수 있음
- 새로고침 시 소실

---

### 2. 전역 메모리(store) 플래그

**장점**

- 라우팅과 무관하게 제어 가능
- 컴포넌트 간 공유 용이

**단점**

- 새로고침 시 초기화
- 탭 단위 생명주기

---

### 3. Storage 기반

#### SessionStorage

- 탭 생명주기 동안 유지

**장점**

- 새로고침 대응 가능

**단점**

- 구현 복잡도 증가
- one-shot UI에는 과한 영속성

---

#### LocalStorage

- 디바이스 단위 영구 유지

**장점**

- 완전한 영속성

**단점**

- Welcome 성격과 부적합
- 상태 정리 책임 증가

---

## 최종 선택

본 프로젝트에서는 Welcome UI를 **별도 페이지로 분리하지 않고**,  
기존 화면 내 **one-shot UI**로 처리하기로 결정했다.

상태 전달은 다음 원칙을 따른다.

- 기본: `location.state` 사용
- 필요 시: 전역 store 보조 사용
- storage 계열은 사용하지 않음

---

## Trade-off

### 👍 얻은 것

- 인증 라우팅 단순화
- 히스토리 오염 방지
- `next` 리디렉션 흐름 안정화
- 불필요한 페이지 전환 제거

### ⚠️ 감수한 것

- 새로고침 시 Welcome 재노출 보장 안 함
- state 기반 UI의 일시성 존재

그러나 Welcome의 성격이 “로그인 직후 1회 안내”이므로,  
이 trade-off는 수용 가능하다고 판단했다.

---

## 회고

이번 의사결정을 통해 다음 기준을 명확히 정리했다.

> **URL은 공유 가능한 상태만 표현하고,  
> 일회성 UI는 상태(state)로 처리한다.**

이는 향후 인증 흐름, 생성 완료 토스트, 온보딩 배너 등  
유사한 one-shot UX 설계의 기준으로 재사용할 수 있다.
